# Spidey v0.1.23

One fix: the app no longer asks you to switch accessibility off and on again every time you
reopen it.

## Why it was asking

An accessibility service runs **inside the app's own process**. Closing the app kills that
process, and the service goes with it — but the *system setting* recording that accessibility
is enabled for Spidey is stored by Android and survives. So every fresh launch began in a state
the app read as broken:

- accessibility reported as **enabled**, from the system setting, which is still set
- the connection reported as **not connected**, because the app's own handle is brand new

Android re-binds enabled accessibility services a moment after the process returns, so the
service was usually working again about a second later. The app judged it instantly, on resume,
and told you to fix something that was about to fix itself. Toggling it was almost certainly
unnecessary.

## What changed

It is only treated as a fault now if it *stays* disconnected. The app keeps re-checking while
it waits, so the warning disappears on its own the moment the service re-attaches — you never
see it for a transient. Only a genuine, persistent failure produces the toggle advice, and the
wording now says it did not connect "even after waiting", which is what makes that advice true
when it appears.

The check that caused this has been removed rather than patched. A single reading can tell you
whether something is connected *right now*; it cannot tell you whether it is stuck, because
that depends on how long it has been that way.
