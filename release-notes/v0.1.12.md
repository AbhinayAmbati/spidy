# Spidey v0.1.12

## What changed

**Stop now stops — immediately, wherever the agent is.** The Stop button on the Home screen
was wired to an empty function, so pressing it there did nothing at all and the task carried
on. That is fixed, and Stop is now a real emergency stop rather than a best-effort one:
pressing it closes a gate that **every** device action checks before it runs, so nothing new
begins — no app launch, no tap, no gesture, no URL. Cancelling the coroutine alone was not
enough, because an action already in flight still finished and launching an app is not
interruptible. There is also a **Stop** button on the notification now, so you can halt a task
from anywhere without finding the app.

**Messaging no longer opens deep links.** Asking the agent to send a message made it open
links that launch a messaging app with the message already composed. Opening a URL is for the
web, so those are refused outright now — `wa.me`, `t.me`, `api.whatsapp.com`, `m.me` and the
`sms:`, `tel:` and `mailto:` schemes — and the agent is told why. To message or call someone it
opens the app and works through its interface, so the message is visible before it is sent and
the send itself still pauses for your approval.

**Repetitive work stops itself.** Two new guards sit alongside the existing exact-repeat
check, which only caught identical arguments:

- If the screen has not changed for **4 consecutive steps**, the task stops and says so.
- If the agent uses **one tool 4 times in a row** without finishing, the task stops. Scrolling,
  waiting and going back are exempt, since using those repeatedly is legitimate.

**The usage guide** ([docs/USAGE.md](docs/USAGE.md)) covers the new Stop behaviour, why
messaging links are refused, and the two new failure messages in its troubleshooting table.

**New tests:** `UrlPolicyTest` and `AgentHaltTest`.
