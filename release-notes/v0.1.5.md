# Spidey v0.1.5

A native Android AI agent. You type a task in plain language — *"Open Chrome and search
for Kubernetes tutorials"* — and it plans the steps, drives your phone through Android's
official APIs, watches what happens on screen, and keeps going until the task is done or
it needs your approval.

This is a **bug-fix release**. If you are on v0.1.4, update — the Test connection button
in that build could not succeed for any provider.

---

## What's fixed in this release

### "Test connection" always failed

Adding a key and tapping **Test connection** always failed with a connection error, for
every provider, regardless of whether the key was valid.

The screen ran inside `viewModelScope`, which is `Dispatchers.Main.immediate`, and the
providers called OkHttp's **blocking** `execute()` directly. So the HTTP request ran on
the main thread and threw `NetworkOnMainThreadException`, which was caught and reported as
a generic connection failure. There was no code path that could have succeeded.

Each provider now performs its request inside `withContext(Dispatchers.IO)`, so it is
correct whichever dispatcher the caller is on. The credential read
(`EncryptedSharedPreferences` does crypto plus disk I/O) is off the main thread too.

Worth knowing: the **agent loop itself was never affected** — it runs on
`Dispatchers.Default`, which permits blocking I/O. The Test button was the casualty.

### Permission "Enable" buttons lingered after the permission was already on

Two separate causes:

- **Stale state.** The Settings cards already hid the button once a permission was
  granted, but the state was read once via `LaunchedEffect(Unit)`. Both grants happen in
  *system* settings, outside the app, so returning never re-read it and the card kept
  offering "Enable". State is now refreshed on `ON_RESUME` in Settings, Home and the
  permissions page.
- **The permissions page never checked state at all.** It unconditionally rendered both
  Enable buttons. It is now stateful and hides each button once granted.

Supporting changes: `PermissionUtils` gained an `isNotificationListenerEnabled` check
(notification access is a separate switch from the `POST_NOTIFICATIONS` runtime
permission, and there was previously no way to test it), and permission cards now show an
explicit **Enabled / Not enabled** label so a hidden button is not ambiguous.

### Carried over from v0.1.4

- **Sarvam AI** provider: `https://api.sarvam.ai/v1`, models `sarvam-105b` and
  `sarvam-105b-conversations`. Note that `sarvam-m` and `sarvam-30b` are deprecated and
  the API now rejects them.
- **Provider error messages** are surfaced instead of bare status codes. Sarvam returns
  **403** for auth failures rather than 401, and that same 403 covers both an invalid key
  and a forbidden request — so the response body is the only way to tell them apart.
- **Configurable auth header**, so Sarvam can use `api-subscription-key` while everything
  else keeps `Authorization: Bearer`.

## Install

1. Download **`spidy.apk`** below.
2. Allow installing from the app you're installing from:
   **Settings → Apps → Special app access → Install unknown apps** → pick Chrome / Files / Drive → **Allow**.
3. Play Protect will warn — *"Unsafe app blocked"* or *"doesn't recognise this app's
   developer"*. That is expected: the signing key is new and has no install history, so
   Google's reputation service has nothing to go on. Tap **More details → Install anyway**.
4. Upgrades cleanly over earlier Spidey builds. If it refuses, uninstall the old one first —
   a build signed with a different key cannot replace it.

**Requires Android 8.0 (API 26) or newer.**

### Try this first

> Open Chrome and search for Kubernetes.

Expect: opening Chrome → finding the search box → typing → pressing search → done.

## Features

- **Home** — one spacious field asking *"What should I do?"*, with voice input and recent tasks.
- **Live task view** — step-by-step status, pause/resume, and a Stop control. Shows what the
  agent is *doing*, never its private chain-of-thought.
- **Confirmation gate** — anything sensitive (send, pay, delete, call, install, confirm)
  pauses and waits for an explicit **Allow**.
- **History** — every task grouped by day, openable to see the actions performed, apps used,
  duration and result.
- **Bring your own key** — OpenAI, Anthropic, Google Gemini, **Sarvam AI**, OpenRouter, or any
  OpenAI-compatible endpoint. Your key is encrypted on-device and sent only to the provider
  you choose.
- **Model picker** — suggested model ids per provider, with a "Custom model…" escape hatch.
- **Memory** — learns app shortcuts from tasks you actually run, viewable and deletable.
- **Terms of Service** — in-app, under Settings → Legal.

## Permissions

| Permission | Why |
| --- | --- |
| **Accessibility** | Required. Lets the agent see and control supported interfaces. You can stop it any time. |
| **Notifications** | Shows progress while a task runs. Optional notification access enables reading notifications. |
| **Internet** | To reach the AI provider you configured. |

Spidy does **not** request `QUERY_ALL_PACKAGES`; it resolves launchable apps through a
declared intent query.

---

## Privacy and security

- Your API key is encrypted on-device and sent only to the provider you chose.
- Screens are summarised into a short list of labelled, interactive elements before anything
  is shared with a model — raw accessibility trees are never dumped.
- Task history, memory and preferences are local-only, and excluded from device backups.
- The model is treated as **untrusted input**. It can only act through the fixed tool
  surface, and every action passes a validator first.
- Android restrictions are explained rather than bypassed.

---

## Known limitations

- **Real-device coverage is thin.** The automation has not been exercised across Chrome,
  Settings, YouTube, Gmail and a messaging app. Apps do not expose identical accessibility
  structures, so selector issues are likely — that is the next piece of work.
- **No screenshots.** Apps that expose nothing useful to accessibility are out of reach.
- **Terms of Service are a template.** Placeholders for the legal entity, jurisdiction and
  contact address are unfilled, and the clauses have not been reviewed by a lawyer.
- Suggested model ids will drift as providers ship new models — use "Custom model…".
- Sarvam's `/v2/chat/completions` (glm5.3, gemma4, deepseekv4-flash) is not wired up; it
  needs per-key beta access.
