# Spidey v0.1.4

A native Android AI agent. You type a task in plain language — *"Open Chrome and search
for Kubernetes tutorials"* — and it plans the steps, drives your phone through Android's
official APIs, watches what happens on screen, and keeps going until the task is done or
it needs your approval.

Not a chatbot in an app, and not an automation dashboard. The whole interface answers one
question: **"What should I do?"**

---

## What's new in this release

**Sarvam AI is now a supported provider.** An India-first model choice alongside OpenAI,
Anthropic, Gemini and OpenRouter. Pick it in Settings → AI provider.

- Base URL `https://api.sarvam.ai/v1`, OpenAI-compatible chat completions.
- Models offered: **`sarvam-105b`** (128K context) and **`sarvam-105b-conversations`** (32K).
- Note for anyone following older guides: `sarvam-m` is deprecated and the API now rejects
  it, and `sarvam-30b` has since been deprecated too. `sarvam-105b` is the current default.

**Better error messages.** Spidey now shows the provider's own explanation instead of a
bare status code. This matters for Sarvam specifically: it returns **403** for auth
failures rather than 401, and that same 403 covers both an invalid key and a
forbidden-but-authenticated request — so the response body is the only way to tell them
apart. It also means a dead model id now says *which* model to use instead, because Sarvam
names the replacement in its error.

**Auth is no longer assumed.** "OpenAI-compatible" describes the request and response
shape, not the auth convention. The adapter now takes the auth header and prefix as
parameters, which is what lets Sarvam use `api-subscription-key` while everything else
keeps `Authorization: Bearer`.

## Install

1. Download **`spidy.apk`** below (2.43 MB).
2. Allow installing from the app you're installing from:
   **Settings → Apps → Special app access → Install unknown apps** → pick Chrome / Files / Drive → **Allow**.
3. Play Protect will warn — *"Unsafe app blocked"* or *"doesn't recognise this app's
   developer"*. That is expected: the signing key is new and has no install history, so
   Google's reputation service has nothing to go on. Tap **More details → Install anyway**.
4. Upgrades cleanly over earlier Spidey builds. If it refuses, uninstall the old one first —
   a build signed with a different key cannot replace it.

**Requires Android 8.0 (API 26) or newer.**

### Try this first

> Open Chrome and search for Kubernetes.

Expect: opening Chrome → finding the search box → typing → pressing search → done.

## Features

- **Home** — one spacious field asking *"What should I do?"*, with voice input and recent tasks.
- **Live task view** — step-by-step status, pause/resume, and a Stop control. Shows what the
  agent is *doing*, never its private chain-of-thought.
- **Confirmation gate** — anything sensitive (send, pay, delete, call, install, confirm)
  pauses and waits for an explicit **Allow**.
- **History** — every task grouped by day, openable to see the actions performed, apps used,
  duration and result.
- **Bring your own key** — OpenAI, Anthropic, Google Gemini, **Sarvam AI**, OpenRouter, or any
  OpenAI-compatible endpoint. Your key is encrypted on-device and sent only to the provider
  you choose.
- **Model picker** — suggested model ids per provider, with a "Custom model…" escape hatch.
- **Memory** — learns app shortcuts from tasks you actually run, viewable and deletable.
- **Terms of Service** — in-app, under Settings → Legal.

## Full changelog since v0.1.0

### Foundation
- Kotlin + Jetpack Compose, Material 3, Hilt, Room, DataStore, Navigation Compose.
- Layered structure: `core` (ai, agent, security, permissions, memory), `data`, `domain`,
  `automation` (accessibility, observer, tools), `ui`, `di`.
- **Agent runtime** — bounded OBSERVE → PLAN → SELECT TOOL → VALIDATE → EXECUTE loop
  (30-step limit), task state machine, confirmation gate.
- **AI layer** — one `AIProvider` interface with adapters for OpenAI-compatible, Anthropic
  and Gemini, resolved through a single factory.
- **BYOK** — keys in `EncryptedSharedPreferences` (Android Keystore), masked in the UI,
  never logged.
- **Automation** — `AccessibilityService` behind a single controller, a compact
  screen-observer that sends labelled elements rather than a raw accessibility tree, and
  16 typed tools behind an `ActionValidator`. The model can never emit code.
- **Persistence** — Room for task history, DataStore for preferences.
- **Foreground service** mirroring progress into a quiet notification.

### UI
- Black / white / brown design system with full light and dark schemes — 36 colour roles
  each, nothing left to Material's baseline palette.
- Splash screen: black background, white wordmark, held briefly.
- **Typography** — Inter for body and UI, Instrument Serif for headings. Both bundled as
  real font files (Inter as static 400/500/600 instances), SIL OFL licensed.
- **Flatter surfaces** — reduced corner radii (4/6/8/10/12dp), no shadow halo, cards defined
  by a hairline border.
- **Tighter controls** — 40dp buttons, agent input row ~60dp, card insets 18dp.
- **Provider icons** — original line-art marks per provider.

### Features added after the first build
- Task detail screen, backed by a Room v1→v2 migration recording each action.
- Long-term memory, with writes gated on the "Remember preferences" toggle.
- Voice input via the platform speech recognizer (no audio permission).
- Pause / resume between steps.
- Bounded conversation context.
- Reduced-motion support, reading the system "remove animations" setting.
- In-app Terms of Service.
- **Sarvam AI provider** *(this release)*.

### Fixes
- **Grey surfaces in light mode.** Only 14 colour roles were set, so Material 3's
  `surfaceContainer*` family fell back to its baseline lavender-grey — that leaked into the
  model picker menu and elsewhere.
- **Card shadow halo.** `Modifier.shadow(..., clip = false)` drew a black-alpha halo around
  cards, muddied by the translucent fill.
- Light-mode card fill raised to 85% white.
- Several compile errors that were breaking CI before tests could run.
- R8 failed the release build on missing Error Prone annotations pulled in by Tink; added
  `-dontwarn` rules.

### Build & release
- Signed release APK built in CI via `assembleRelease`, signing material from repository
  secrets (keystore never committed).
- `apksigner verify --print-certs` runs on every release.
- Artefact named `spidy.apk` rather than the default `app-release.apk`.
- Unit tests, debug APK and test reports uploaded on every CI run.
- Release notes read from `release-notes/<tag>.md`.

## Permissions

| Permission | Why |
| --- | --- |
| **Accessibility** | Required. Lets the agent see and control supported interfaces. You can stop it any time. |
| **Notifications** | Shows progress while a task runs. Optional notification access enables reading notifications. |
| **Internet** | To reach the AI provider you configured. |

Spidy does **not** request `QUERY_ALL_PACKAGES`; it resolves launchable apps through a
declared intent query.

## Privacy and security

- Your API key is encrypted on-device and sent only to the provider you chose.
- Screens are summarised into a short list of labelled, interactive elements before anything
  is shared with a model — raw accessibility trees are never dumped.
- Task history, memory and preferences are local-only, and excluded from device backups.
- The model is treated as **untrusted input**. It can only act through the fixed tool
  surface, and every action passes a validator first.
- Android restrictions are explained rather than bypassed.

## Known limitations

- **Real-device coverage is thin.** The automation has not been exercised across Chrome,
  Settings, YouTube, Gmail and a messaging app. Apps do not expose identical accessibility
  structures, so selector issues are likely — that is the next piece of work.
- **No screenshots.** Apps that expose nothing useful to accessibility are out of reach.
- **Terms of Service are a template.** Placeholders for the legal entity, jurisdiction and
  contact address are unfilled, and the clauses have not been reviewed by a lawyer.
- Suggested model ids will drift as providers ship new models — use "Custom model…".
- Sarvam's `/v2/chat/completions` (glm5.3, gemma4, deepseekv4-flash) is not wired up; it
  needs per-key beta access.
