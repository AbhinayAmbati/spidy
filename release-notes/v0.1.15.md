# Spidey v0.1.15

## Fixed: tasks stopping the instant they started

**This release fixes a regression I introduced in v0.1.14.** Touch-to-stop was firing when
nobody had touched the screen, so a task stopped right after opening the app — the task view
read *"Stopped: you touched the screen"* at step 0. I shipped that feature knowing I could not
verify it on a device, and it turned out to be too eager. Sorry.

The cause is timing. The tap that *starts* a task is itself a touch, and Android batches
accessibility events — the service asks for a 300 ms notification timeout — so that event can
arrive **after** the task is already running. With nothing to distinguish it from a real
interruption, the agent stopped itself immediately.

Two changes:

- **Touch-to-stop now arms 2.5 seconds into a task.** The tap that started it has long been
  delivered by then, so it cannot be mistaken for the user taking over.
- **A setting: Settings → Safety → "Stop when I touch the screen"** (on by default). If it
  ever stops when you did not mean it to, you can turn it off immediately instead of waiting
  for a fix. This should have existed from the start for a feature that can end a task.

The decision now lives in one place, `UserTouchGate.shouldStopForUserTouch`, with every reason
not to stop in it — turned off, the agent waiting on an answer, the opening seconds of a task,
and the agent's own taps, which raise exactly the same platform events a finger does.

**New tests** cover each of those guards individually, including that any single one being off
is enough to prevent a stop.

## If it still stops on its own

Turn it off at **Settings → Safety → "Stop when I touch the screen"**, and tell me what you
were doing. That is the one part of this feature I cannot test from here.
