# Spidey v0.1.16

## Fixed: the agent reading its own movement as your finger

**This is the fix for touch-to-stop firing when you had not touched anything.** You reported
that a task stopped with *"you touched the screen"*, that turning the setting off made
everything work, and you asked whether the agent's own movement was being mistaken for a
touch. It was, and the cause was a clock.

The decision was timing touches with **when the app heard about them** instead of **when they
happened**. Android delivers accessibility events late, and on a slow run — opening YouTube,
waiting for the model, settling the screen — the event raised by the agent's own tap arrived
long after the window that would have excused it. So the agent's gesture read as you taking
over, and the task stopped.

It now uses `AccessibilityEvent.getEventTime()` — the moment the touch occurred — so a late
delivery changes nothing. Every clock in the decision is the same one the platform stamps
events with, and the decision is now correct regardless of how slow the device is.

Two smaller consequences of the same change:

- The window that excuses the agent's own taps is judged against when they happened, so a
  slow device can no longer outrun it.
- The tap that *starts* a task is also judged by when it happened, so the opening grace
  period now reliably covers it.

**Tests** include the exact failure: an event from the agent's own gesture delivered seconds
late must still be suppressed, while the same event time with the agent already finished must
not be. Also pinned: an event with no usable timestamp never stops a task.

**If it still stops on its own**, turn it off at **Settings → Safety → "Stop
when I touch the screen"** and tell me — but this was a real bug and it should be gone.
