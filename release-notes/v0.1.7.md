# Spidey v0.1.7

A native Android AI agent. You type a task in plain language — *"Open Chrome and search
for Kubernetes tutorials"* — and it plans the steps, drives your phone through Android's
official APIs, watches what happens on screen, and keeps going until the task is done or
it needs your approval.

This is a **bug-fix release** for three reported failures. If you are on v0.1.6 or earlier,
update.

---

## What's fixed

### "Test connection" failed with *"… is not a JsonArray"*

The real error was a serialization crash inside our own response parsing. The providers
used kotlinx.serialization's **throwing** accessors (`jsonObject`, `jsonArray`,
`jsonPrimitive`), which raise an `IllegalArgumentException` on any value that is not the
expected type — **including a JSON `null`**, which providers legitimately return for fields
like `tool_calls`. That exception was not wrapped, so it escaped as a generic
"connection failed" and hid the fact that the connection itself was fine.

All three providers now use **safe casts**, so an unexpected type or a null is handled
rather than fatal. Parse failures now also include the first 200 characters of the
provider's actual response, so the cause is visible instead of inferred.

### Accessibility: *"this service is malfunctioning"*

The service was registered for `typeViewTextChanged`, `typeViewScrolled`,
`typeViewFocused` and `typeViewClicked` **in addition to** the window-level events, with no
package filter. Those four fire constantly, and nothing in the app consumed them — the
screen observer polls instead. That was pure load, and a service the system considers
unresponsive gets flagged and disabled.

- Event types narrowed to `typeWindowStateChanged | typeWindowContentChanged |
  typeWindowsChanged`.
- `notificationTimeout` raised from 120 ms to 300 ms.
- **Every callback is now guarded.** Android treats an accessibility service that throws as
  malfunctioning, so a bug in our code must never be able to escape a callback and take the
  service down.

### Notification access kept asking to be turned on

The check compared the whole `ComponentName` for equality against the raw entry from the
system's `enabled_notification_listeners` string. That string is a colon-separated list
that can carry whitespace, and any mismatch silently reads as "not enabled" — so the app
kept asking even after the switch was on. Matching is now tolerant: entries are trimmed and
compared explicitly by package name and class name. The same fix applies to the
accessibility check.

## Install

1. Download **`spidy.apk`** below.
2. Allow installing from the app you're installing from:
   **Settings → Apps → Special app access → Install unknown apps** → pick Chrome / Files / Drive → **Allow**.
3. Play Protect will warn — *"Unsafe app blocked"* or *"doesn't recognise this app's
   developer"*. That is expected: the signing key is new and has no install history. Tap
   **More details → Install anyway**.
4. Upgrades cleanly over earlier Spidey builds. If it refuses, uninstall the old one first.

**After updating, turn accessibility off and back on once.** The system caches the previous
declaration, so it will not re-bind on its own.

**Requires Android 8.0 (API 26) or newer.**

### Try this first

> Open Chrome and search for Kubernetes.

Expect: opening Chrome → finding the search box → typing → pressing search → done.

## Features

- **Home** — one spacious field asking *"What should I do?"*, with voice input and recent tasks.
- **Live task view** — step-by-step status, pause/resume, and a Stop control.
- **Confirmation gate** — anything sensitive (send, pay, delete, call, install, confirm)
  pauses and waits for an explicit **Allow**.
- **History** — every task grouped by day, openable to see the actions performed, apps used,
  duration and result.
- **Bring your own key** — OpenAI, Anthropic, Google Gemini, Sarvam AI, OpenRouter, or any
  OpenAI-compatible endpoint. Your key is encrypted on-device and sent only to the provider
  you choose.
- **Model picker** — suggested model ids per provider, with a "Custom model…" escape hatch.
- **Memory** — learns app shortcuts from tasks you actually run, viewable and deletable.
- **Terms of Service** — in-app, under Settings → Legal.

## Permissions

| Permission | Why |
| --- | --- |
| **Accessibility** | Required. Lets the agent see and control supported interfaces. You can stop it any time. |
| **Notifications** | Shows progress while a task runs. Optional notification access enables reading notifications. |
| **Internet** | To reach the AI provider you configured. |

Spidy does **not** request `QUERY_ALL_PACKAGES`; it resolves launchable apps through a
declared intent query.

## Privacy and security

- Your API key is encrypted on-device and sent only to the provider you chose.
- Screens are summarised into a short list of labelled, interactive elements before anything
  is shared with a model — raw accessibility trees are never dumped.
- Task history, memory and preferences are local-only, and excluded from device backups.
- The model is treated as **untrusted input**. It can only act through the fixed tool
  surface, and every action passes a validator first.
- Android restrictions are explained rather than bypassed.

---

## Known limitations

- **Real-device coverage is thin.** The automation has not been exercised across Chrome,
  Settings, YouTube, Gmail and a messaging app. Apps do not expose identical accessibility
  structures, so selector issues are likely — that is the next piece of work.
- **No screenshots.** Apps that expose nothing useful to accessibility are out of reach.
- **Terms of Service are a template.** Placeholders for the legal entity, jurisdiction and
  contact address are unfilled, and the clauses have not been reviewed by a lawyer.
- Suggested model ids will drift as providers ship new models — use "Custom model…".
- Sarvam's `/v2/chat/completions` (glm5.3, gemma4, deepseekv4-flash) is not wired up; it
  needs per-key beta access.
