# Spidey v0.1.19

Phases 2 and 3 of the performance work: fewer model calls, then none at all.

## Phase 2 — one model call can drive several actions

This is the change that actually gets a multi-action task under five seconds. At roughly
1.25 s per call, a five-action task costs six seconds of model time *before the phone does
anything* — no amount of tuning fixes that. The fix is to stop making five calls.

**The model may now return several tool calls in one reply.** The agent records that single
assistant turn, runs the calls in order, and verifies each one exactly as before — so
confirmations, the loop guards, step timing and history all still apply per action.

**A batch stops the moment something goes wrong.** If any action fails, is refused, or is
declined, the rest of the batch is abandoned and the agent is asked again. The remaining
actions were planned against a screen that no longer holds, so re-planning beats pushing on.

The prompt is explicit about when batching is appropriate: two or three steps you are certain
about, and never a step whose target depends on what the previous step showed. `finish` is
never batched.

All three providers are supported: OpenAI `tool_calls`, Anthropic `tool_use` blocks, and
Gemini `functionCall` parts. Anthropic and Gemini expect every result for one assistant turn
inside a *single* user turn, so consecutive results are merged rather than sent as separate
turns they would reject.

## Phase 3 — routines: replay a task with no model at all

When a task finishes, **Save as routine** keeps it. Running a routine makes **no model calls
and costs no tokens** — it is bounded only by how fast the phone is.

A routine is a recording, so it is only valid while the screens it touches still look the
same. Every step is therefore verified as it runs, and **the moment a step does not match the
agent hands the task over to the model from that point** — it does not fail, and it does not
blindly replay the rest. A routine that has gone stale degrades into a normal agent run
rather than breaking.

Because a replay needs no model, **it also needs no API key**. You can run a saved routine
without a provider configured at all.

Routines live under **Settings → Routines**: run, delete, and see how often each has been used.
