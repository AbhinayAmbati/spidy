# Spidey v0.1.20

Everything here came from the failure screenshots you sent, not from analysis.

## A fumbled tool call no longer ends the task

"Task failed. The model returned something I couldn't understand." at **step 0** was the app
throwing away a whole run because the model sent a shape the schema hadn't asked for —
`{"target":"Search"}`, a bare string where an object belongs. Arguments are now coerced into
shape first: a string target becomes an object, a target nested one level too deep is
flattened, numbers and strings are converted either way. Anything genuinely unreadable is now
shown back to the model to retry instead of killing the run.

## It stops doing the same thing twice

The same app being reopened five times, and the same text retyped six times. The old guard only
refused a repeat when the screen was byte-identical to last time — and the keyboard sliding in
makes two runs that accomplished nothing look different. Each exact action is now counted, and
refused past a limit. Deliberately not applied to tapping, because paging through a list by
tapping "Next" five times is a real task.

## The nudge loop

"The model kept replying with text instead of acting" appeared twice. The nudge carried no
screen at all, so the model was told off for talking and given nothing to act on. It now
carries the screen, and the budget is four attempts instead of two. Searching the web is also
now a hard rule: one `launch_url` call with the search URL, not a browser driven by hand — a run
that took eighteen steps is what that rule prevents.

## New: a status pill over other apps

A small pill above the bottom edge showing what the agent is doing — the current step, and
"Step 3 of 30" — while you are in another app. A finished task shows Done/Failed/Stopped for
two seconds before it goes. It can never be tapped, so it cannot swallow an action the agent
needs to make. **Settings → Safety → Show status over other apps** to enable it.
