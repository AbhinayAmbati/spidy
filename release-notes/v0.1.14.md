# Spidey v0.1.14

## What changed

**Touch-to-stop: put a finger on the screen and the agent stops.**

This is the control that works when nothing else does — when the app is buried, the Stop
button is off-screen, or the agent has navigated somewhere you did not expect. Any touch on
the screen while a task is running halts it on the spot, and the task view says so: *"Stopped:
you touched the screen."*

Making it work needed one non-obvious thing. The agent drives the phone with
`dispatchGesture`, which raises **exactly the same platform touch events as a real finger** —
so a naive version would stop the agent every time it tapped something. Every action the agent
performs therefore opens a short suppression window (the gesture's own duration plus a
generous margin), and anything outside that window is you. The margin is deliberately wide: a
false stop is far worse than a missed one.

It is also **suppressed while the agent is waiting on you.** When it asks for confirmation or
asks a question, your touch is the *answer* — stopping the task at that moment would make the
dialog impossible to use.

The accessibility service now subscribes to `typeTouchInteractionStart`, which is the one
high-frequency event the app genuinely consumes.

**New tests:** `UserTouchGateTest` pins the touch-versus-self-gesture decision, including that
the window covers the gesture, that a stale window does not suppress a later touch, and that
other event types are never mistaken for one.

**The usage guide** ([docs/USAGE.md](docs/USAGE.md)) documents the behaviour and adds both new
messages to its troubleshooting table.

## Important after updating

**Turn accessibility off and back on once.** The new event subscription is part of the service
declaration, and Android caches the previous one — without the toggle, touch-to-stop will not
be registered.
