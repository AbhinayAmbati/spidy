# Spidey v0.1.8

A native Android AI agent. You type a task in plain language — *"Open Chrome and search
for a topic"* — and it plans the steps, drives your phone through Android's official
APIs, watches what happens on screen, and keeps going until the task is done or it needs
your approval.

This release fixes **the bug that stopped every task at step 0**. If you are on v0.1.7 or
earlier, update — nothing could ever run before this.

---

## The fix that matters

**Every task failed at "Step 0 of 30" with *"The model returned something I couldn't
understand."***

That message was hiding a plain bug in how tool calls were read. When a model calls a tool,
the provider sends two separate things:

```
name       "open_app"                      <- the action
arguments  {"packageName":"com.android.chrome"}   <- its parameters
```

But the action schema our code decoded into **requires an `action` field**, and the tool
schemas we send to the model declare *only* the parameters — `open_app` takes `packageName`
and nothing else. So the arguments never contained an `action`, decoding failed with
*"Field 'action' is required"*, and every single tool call was discarded. The tool's name
**is** the action; it just had to be merged in before decoding.

The fix is one shared codec (`AgentActionCodec`) used by all three providers — OpenAI,
Anthropic and Gemini. All three had the same flaw, so no provider ever worked.

Alongside it:

- **The real error is no longer thrown away.** Parse failures used to be replaced with a
  canned "try rephrasing" line, which is precisely why this was hard to pin down. The
  provider's or parser's actual message is now shown.
- **A text reply is no longer mistaken for success.** Completion is signalled by the
  `finish` tool, so a reply with no tool call used to be reported as a *completed* task
  with the model's prose as the result. It now nudges the model to act (twice), then fails
  honestly and suggests a model that supports tool calling.
- **Malformed arguments degrade instead of crashing.** If the parameters are unreadable but
  the tool name is known, the action is still built and the tool's own validator rejects it
  with a reason the model can act on — e.g. *"A target is required to click"* — so it can
  retry instead of the task dying.

A regression test (`ToolCallActionCodecTest`) now covers the real tool-call shape. The
existing tests only ever fed in JSON that already contained an `action`, which is why they
stayed green while the app could not take a single step.

## Install

1. Download **`spidy.apk`** below.
2. Allow installing from the app you're installing from:
   **Settings → Apps → Special app access → Install unknown apps** → pick Chrome / Files / Drive → **Allow**.
3. Play Protect will warn — *"Unsafe app blocked"* or *"doesn't recognise this app's
   developer"*. That is expected: the signing key is new and has no install history. Tap
   **More details → Install anyway**.
4. Upgrades cleanly over earlier Spidey builds. If it refuses, uninstall the old one first.

**After updating, turn accessibility off and back on once.** The system caches the previous
declaration, so it will not re-bind on its own.

**Requires Android 8.0 (API 26) or newer.**

### Try this first

> Open Chrome and search for a topic.

Expect: opening Chrome → finding the search box → typing → pressing search → done.

If the *model* now returns a tool call but the screen doesn't match what it expects, that is
a different (selector) problem — tell me the app and what the screen did.

## Features

- **Home** — one spacious field asking *"What should I do?"*, with voice input and recent tasks.
- **Live task view** — step-by-step status, pause/resume, and a Stop control.
- **Confirmation gate** — anything sensitive (send, pay, delete, call, install, confirm)
  pauses and waits for an explicit **Allow**.
- **History** — every task grouped by day, openable to see the actions performed, apps used,
  duration and result.
- **Bring your own key** — OpenAI, Anthropic, Google Gemini, Sarvam AI, OpenRouter, or any
  OpenAI-compatible endpoint. Your key is encrypted on-device and sent only to the provider
  you choose.
- **Model picker** — suggested model ids per provider, with a "Custom model…" escape hatch.
- **Memory** — learns app shortcuts from tasks you actually run, viewable and deletable.
- **Terms of Service** — in-app, under Settings → Legal.

## Permissions

| Permission | Why |
| --- | --- |
| **Accessibility** | Required. Lets the agent see and control supported interfaces. You can stop it any time. |
| **Notifications** | Shows progress while a task runs. Optional notification access enables reading notifications. |
| **Internet** | To reach the AI provider you configured. |

Spidy does **not** request `QUERY_ALL_PACKAGES`; it resolves launchable apps through a
declared intent query.

---

## Privacy and security

- Your API key is encrypted on-device and sent only to the provider you chose.
- Screens are summarised into a short list of labelled, interactive elements before anything
  is shared with a model — raw accessibility trees are never dumped.
- Task history, memory and preferences are local-only, and excluded from device backups.
- The model is treated as **untrusted input**. It can only act through the fixed tool
  surface, and every action passes a validator first.
- Android restrictions are explained rather than bypassed.

---

## Known limitations

- **Real-device coverage is still thin.** Selector heuristics have not been exercised across
  Chrome, Settings, YouTube, Gmail and a messaging app, so a step may not find the element it
  wants. That is the next piece of work.
- **No screenshots.** Apps that expose nothing useful to accessibility are out of reach.
- **Models without tool calling will not work.** The app now says so plainly instead of
  pretending the task finished.
- **Terms of Service are a template.** Placeholders for the legal entity, jurisdiction and
  contact address are unfilled, and the clauses have not been reviewed by a lawyer.
- Suggested model ids will drift as providers ship new models — use "Custom model…".
- Sarvam's `/v2/chat/completions` (glm5.3, gemma4, deepseekv4-flash) is not wired up; it
  needs per-key beta access.
